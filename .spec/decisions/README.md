# Decisions(决策记录 · ADR)

用 ADR(Architecture Decision Record)记录决策:为什么这样选、为什么不选别的、为什么划这条边界。**本目录是全仓决策记录的唯一落点**——玩法、美术、技术、流程上的决策都记这里,知识文档只描述现状,不留决策记录。只记用户拍板的决定。

## 怎么写一条 ADR

- 一个决策 = 一个文件 `NNNN-<slug>.md`,编号从 `0001` 递增,不撞号;写完在下方索引加一行。初始化时写第一条 `0001`:项目结构与技术路线。
- **一旦记录不改写**:被推翻就新增一条,把旧的状态标成「被 NNNN 取代」,历史留痕。被取代的状态行必须链接取代者(spec-lint 检查)。
- 无 frontmatter。格式照抄:

  ```markdown
  # NNNN · <一句话决策>

  - 日期:YYYY-MM-DD
  - 状态:生效 | 被 [NNNN](NNNN-<slug>.md) 取代(部分取代加前缀「部分」)

  ## 背景
  面对什么问题。

  ## 决策
  定了什么。

  ## 后果
  接受了什么代价。
  ```
