# bug 墙

**怎么整理**：满 200 行时不再往里加，告诉用户「该复盘了」，用户同意再按 `spec-steward` 技能的「复盘」做；用户说「整理 bug 墙」「复盘」时也一样。只有复盘时才通读本文件。

**记什么**：判据是「换一个 Agent 下次还可能犯吗」。设计遗漏、规范没写清、框架问题、会重犯的实现错误要记；手误和一次性的低级错误修完不记，已修、未修都按这个判据。只记四个来源：开发中修不了的、大需求合完后的最后一遍测试、用户报的、reviewer 审出的；合入前自己写错又改掉的不记。

**怎么记**：一条 bug 一行，加在表格最后。记之前用关键词 grep 本文件查重，不读全文。同类第二次出现，在备注里标「重犯，同第 N 行」；第三次出现，必须升格成 `standards/` 规范或红线；规范已写但还重犯，说明那条规范要改写。到 200 行按上面「怎么整理」做。
