# 系统规则（每次开工先读）

只写「必须 / 只能 / 不得」，后面一句话说为什么。做法和细节在 [knowledge/lumio/](../knowledge/lumio/)。用户新定下的项目红线加在本文件末尾，一条一节。

## 连接 Lumio

- **正式构建只能用 `connectLumioFromLaunch()` 连平台；连接失败时必须把错误显示给玩家，不得自动换成模拟器或本地假数据。**——在平台上假装成功会让玩家以为进度已存好，实际已经丢了。
- **模拟器只能在本地开发构建里用，并且必须在构建时剔除。**——检查办法：正式构建的脚本里搜不到 `simulated_friend`（只有模拟器模块里有）。
- **不得启用 SDK 的 `firstParty` 选项；不得调用好友、私信、联机接口。**——这些首版只对平台自己的应用开放，声明了也不会授予。
- **每次调用都必须检查返回的 `ok`，失败时按 `failure.code` 给出明确提示，不得伪造成功或静默吞掉。**
- **存档写入必须带上读出来的 `expectedRevision`（新槽用 `null`）；遇到冲突必须保留玩家当前进度、重新读取后让玩家决定，不得自动覆盖云端。**

## 打包与上传

- **ZIP 根目录必须直接放入口 HTML 和 `lumio.json`，不得再套一层文件夹。**——平台按包根找文件。
- **`lumio-bootstrap.js` 不得放进 ZIP。**——它由平台在上线时注入；入口页可以用相对路径 `./lumio-bootstrap.js` 引用它。
- **页面里的资源路径必须是相对路径，不得以 `/` 开头。**——游戏在平台上不在域名根目录。
- **上传的只能是构建产物，不得依赖 `node_modules`、开发服务器或本机文件。**
- **用到的存档槽、游戏字段、排行榜必须先在 `lumio.json` 里声明；外部网络只能声明精确的 https / wss 来源，不得用通配或平台域名。**
- **打包必须用 `tools/lumio-pack.mjs`（或做同样检查的工具）。上传、提交审核由用户在创作中心自己操作，Agent 不得替用户上传。**

## 账号与数据

- **游戏里不得做账号密码登录，不得索取或保存平台账号、Cookie、令牌。**——登录和资料授权由平台负责，游戏只拿到本游戏的玩家号和玩家同意给的资料。
- **密钥、令牌不得写进游戏代码或提交进仓库。**——网页游戏的代码玩家都能看到。

## 文档

- **`.spec/knowledge/` 只写现状；改了设计就改文档，不留「以前是这样」。**——历史在 git 里。
- **决策写进 `.spec/decisions/`，已接受的 ADR 不得改写，要推翻就新写一条并标明取代关系。**
- **只有用户拍板的结论才写进 `.spec/`；讨论中的想法留在对话里。**

## 对外操作

- **推送到远程仓库、建远程仓库、发布、对外发消息之前必须先问用户。**
- **不得替用户安装 Node 等系统软件，不得修改用户电脑的系统设置。**
