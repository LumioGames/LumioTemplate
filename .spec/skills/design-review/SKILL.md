# Design Review(策划评审)

对照策划案与架构约束审查策划文档与开发需求,产出三级裁决与可执行修改意见。文档基准在 `.spec/knowledge/project.md`(项目一页纸)和 `.spec/knowledge/features/`(数值来源纪律见 [design-director](../design-director/SKILL.md))——审查只对照、不立法。

## 何时使用

- 收到策划案、玩法方案、需求单需要评审。
- 策划案定稿前的质检;检查设计是否偏离既定方向。

## 操作步骤

1. **定基准(含降级)。** 读项目一页纸、对应的功能文档,以及按 ADR 0001(`.spec/decisions/0001-project-structure.md`)现查的技术约束。**策划案未建立时**:显式声明「无策划案在案,按架构约束 + 会话内临时基准评审,结论不具约束力」;评审后把暴露出的空白路由 design-director 定调——**绝不静默发明规范**。
2. **四层对照,前层不过后层不看。**
   - **L1 架构可行性**:逐条过技术约束。**这一层不过,后面全部不用看**——设计再好,做不出来等于零。能直接判的约束(局时、人数、是否联机、存档放哪)先过。
   - **L2 方向符合性**:产品支柱逐条对照;与已定稿策划案的上下游是否一致;是否偏离既有定调。
   - **L3 数值来源完整性**:每个数值是否带「已验证 / 推断待验证 / 引用」标注;推断值是否都写清了验证方式。
   - **L4 验收可判定性**:文档的验收问题能否回答是 / 否;需求单的验收标准能否客观验证。界面要还原设计稿、参考图的,验收必须按下面「视觉验收」拆成维度、写明量什么和容差,只写「100% 还原」「看起来一致」的退回。
3. **裁决(三级)。** 通过 / 有条件通过(条件清单 + 截止时间,登记为债务、不阻塞下游)/ 退回。退回意见每条:问题定位(文档路径 + 章节)+ 违反条款(降级模式注明临时基准)+ **数值化期望**(「局时上限写成 3 分钟」,不写「局时短一点」)+ 严重级;单次退回聚焦 ≤3 个主要问题,小毛病并入条件清单。
4. **回流。** 值得记的问题按 `.spec/knowledge/bug-wall.md` 开头的规则记一行(同类第二次标重犯);同类退回 3 次 → 用 design-director 定调并补条款。

## 视觉验收(界面还原类需求)

需求单写验收、实现完成后验收,都按这张表拆开,不合成一个「完成度」。每一条都写明**量的是什么**(哪个控件或哪类资源、在哪个尺寸下、和什么比),需求单另写了容差的以需求单为准:

| 维度 | 量什么 | 默认容差 |
|---|---|---|
| 几何 | 控件外框的位置和尺寸,在设计尺寸下和设计稿 / 蓝图的坐标比 | ±4 设计像素 |
| 文字 | 每个文字控件的内容、字号、颜色、描边,有没有溢出或意外换行;每种语言各量一遍 | 完全一致 |
| 层级 | 谁盖住谁、弹窗和遮罩的前后顺序,和设计稿比 | 完全一致 |
| 原创素材 | 资源清单逐项:有出图记录或来源,不含参考图里的角色、图标、商标、文字 | 逐项全过 |
| 动效 | 起点、终点的位移和播完后的终态(不只看「在播放」);时长 | 位移、终态按几何容差;时长按需求单 |
| 适配 | 每个标准尺寸下:控件在安全区里、不互相遮挡、按钮能点到 | 每个尺寸全过 |

- **Agent 先验第一遍,人再看。** 能量的维度由 Agent 用工具量出来(截图、坐标对比、测试),逐条填表、附证据;表填完、自己能修的先修,再请用户看整体观感。用户的观感意见按 art-review 处理。
- **编号对编号,不比总数。** 需求逐条编号,每条分别登记:对应哪段实现、实际跑了哪项检查、视觉证据在哪。测试数、资源数、截图数超过要求不等于完成——多写的用例填不了缺的需求编号,资源总数也不等于界面真用到的数。
- **没量的照实写。** 只是目测的写「目测」,没做的写「未执行」;不说「逐像素一致」,除非真的逐像素比过。

## 快速参考(域 × 差异化检查点)

| 域 | 检查点 |
|---|---|
| 玩法 | 规则能否很快讲清;失败时玩家知不知道自己错在哪;在目标设备上操作是否顺手 |
| 系统 | 是否服务核心循环;新玩家第一局会不会被系统挡住 |
| 数值 | 有无上限防滚雪球;落后方翻盘路径;每个数字来源齐全 |
| 关卡 | 节奏和难度曲线;空间大小与移速、局时是否匹配 |
| 商业化 | 付费点和核心体验的边界;与项目一页纸的定位是否冲突 |

通用评判维度见 [design-director](../design-director/SKILL.md) 的通用维度表,此处不复述。

## 注意事项(Pitfalls)

- **架构可行性优先。** L1 不过 = 整体不通过,不必再评玩法好坏。
- **无文档不硬审。** 降级必须显式声明,结论不具约束力。
- **裁决要引条款。** 「感觉不好玩」不是审查意见。
- **审查不顺手立法。** 空白走定调流程,不在审查里现编规范。
- **数值无来源 = 未完成。** 不因「看起来合理」放行。

## 验证

- 基准来源已声明(策划案章节 / 临时基准)。
- 四层逐层过,L1 结论明确;界面还原类需求的验收已按「视觉验收」拆维度、写明量什么和容差。
- 三级裁决明确;每条意见含定位、依据、数值化期望、严重级。
- 规范空白与复发问题已回流,或声明无。
