# 立项问题（第一段）

一轮问完下面 5 个问题，不要一个一个地来回问。每题都说清楚它决定什么、给一个例子、给默认值。用户没想好、或说「你定」，就用默认值，并在生成的文件里那一处标「Agent 代定，可以改」。

可以这样开场（按用户的语言改写）：

> 我先问 5 个问题，用来决定项目要建哪些文件夹、写哪些规范。没想好的可以说「你定」，我按括号里的默认值来，以后都能改。

## 1. 暂定名，一句话说说想做什么

- **决定什么**：`.spec/AGENTS.md` 的「项目是什么」、README 的标题和介绍。
- **例子**：「星跳：一只小猫在星星之间跳，越跳越高，摔下来就重来。」
- **默认值**：暂定名「新游戏」；一句话标「待完善」，第二段聊玩法时补。
- **顺带定英文短名**：小写字母、数字和连字符（如 `star-hop`），以后用作工程名和打包文件名。用户不给就按暂定名转写一个，告诉用户。

## 2. 有没有要自己写的服务端代码

- **决定什么**：要不要建 `Server/`；`Config/` 里要不要放客户端和服务端之间的协议。
- **怎么算「有」**：要自己写联机对战的房间和同步逻辑、自己搭后台。只用平台提供的云存档、排行榜、成就**不算**。
- **例子**：「多人实时对战，房间和同步自己写」→ 有；「单机闯关，进度存在 Lumio 云存档里」→ 没有。
- **默认值**：没有。

## 3. 打算用什么做：网页、Unity、UE 还是别的

- **决定什么**：`Client/README.md` 用哪一份模板，里面写清楚以后怎么建工程；要不要保留 LGUI 的网页构建脚本；代码风格的默认值。
- **说明**：每条路线都推荐用 [LGUI](https://github.com/LumioGames/LGUI) 做界面：网页直接用；目标是 Unity 时，界面在 LGUI 里做好再导出到 Unity；UE 没有 LGUI 后端，可以先用网页做原型验证玩法。
- **例子**：「网页，手机浏览器里玩」→ 网页；「Unity，以后上手机应用商店」→ Unity。
- **默认值**：网页（界面用 LGUI）。

## 4. 发不发布到 Lumio

- **决定什么**：`rules/project.md` 要不要加 Lumio 平台红线；要不要保留 Lumio 打包工具 `lumio-pack.mjs`。不发布也会保留 `.spec/knowledge/lumio-platform/`，以后改主意还能用。
- **例子**：「先发到 Lumio 给朋友玩」→ 发布；「只在自己的网站上放」→ 不发布。
- **默认值**：发布。

## 5. 几个人做；文档和注释用中文还是英文

- **决定什么**：`workflow.md` 的分支和合并方式（一个人直接在 `main` 上提交；多人用功能分支加 PR），`code-style.md` 的语言约定。
- **例子**：「就我一个，中文」；「三个人，文档中文、代码注释英文」。
- **默认值**：一个人；中文。

## 答案之间要提醒的地方

- **选了 Unity、UE 或其他路线，又要发布到 Lumio**：告诉用户 Lumio 收的是网页包（ZIP 里直接放入口 HTML 和 `lumio.json`，见 `.spec/knowledge/lumio-platform/publishing.md`）；这个引擎能不能导出成这样的网页包，建工程时再确认。照用户的选择生成，不替用户改路线。
- **有自己的服务端，又要发布到 Lumio**：告诉用户平台的好友、私信、联机能力不对第三方开放；游戏可以连自己的服务器，地址要在 `lumio.json` 的 `network.connect` 里写成精确的 `https://` 或 `wss://` 来源（见 `.spec/knowledge/lumio-platform/sdk.md` 和 `publishing.md`）。
