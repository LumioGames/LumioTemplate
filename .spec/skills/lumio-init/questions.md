# 立项问题（第一段）

一轮问完下面 4 个问题，不要一个一个地来回问；第 4 题（引擎）通常只要用户点个头。每题都说清楚它决定什么、给一个例子、给默认值。用户没想好、或说「你定」，就用默认值，并在生成的文件里那一处标「Agent 代定，可以改」。

后面「不问，直接用默认值」的几项（几个人做、英文短名、文档语言）不放进问题里，只在复述时列出来，用户想改再改。

可以这样开场（按用户的语言改写）：

> 我先问几个问题，用来决定项目要建哪些文件夹、写哪些规范。没想好的可以说「你定」，我按括号里的默认值来，以后都能改。

## 1. 暂定名，一句话说说想做什么

- **决定什么**：`.spec/AGENTS.md` 的「项目是什么」、项目一页纸、README 的标题和介绍。
- **例子**：「星跳：一只小猫在星星之间跳，越跳越高，摔下来就重来。」
- **默认值**：暂定名「新游戏」；一句话标「待完善（定玩法时）」。

## 2. 有没有要自己写的服务端代码

- **决定什么**：要不要建 `Server/`；`Config/` 里要不要放客户端和服务端之间的协议。
- **怎么算「有」**：要自己写联机对战的房间和同步逻辑、自己搭后台。只用平台提供的云存档、排行榜、成就**不算**。
- **例子**：「多人实时对战，房间和同步自己写」→ 有；「单机闯关，进度存在 Lumio 云存档里」→ 没有。
- **默认值**：没有。

## 3. 发布到哪（可以多选）

- **决定什么**：`Builds/` 按哪些发布目标分子目录；`rules/project.md` 要不要加 Lumio 平台红线；第 4 题推荐什么引擎。
- **选项**：网页、Lumio、微信 / 抖音小游戏、Steam（PC）、安卓、iOS、主机。不发布到 Lumio 也会保留 `.spec/knowledge/lumio-platform/` 和打包工具，以后改主意还能用。
- **例子**：「先发到 Lumio 给朋友玩」→ Lumio；「Steam 上卖，以后出手机版」→ Steam、安卓、iOS。
- **默认值**：Lumio。

## 4. 引擎：默认网页 + LGUI，只问一句

- **决定什么**：`Client/README.md` 用哪一份模板，里面写清楚以后怎么建工程；代码风格的默认值。
- **怎么问**：和第 3 题在同一轮问，只问一句「就用这个可以吗」：
  - 发布目标只有网页、Lumio（或用户没想好）：「引擎和界面就用网页 + LGUI：在浏览器里就能试玩、改得快，做好能直接发到 Lumio。可以吗？」
  - 发布目标里有别的平台：按下表说出推荐的引擎和一句理由，并说默认先用网页 + LGUI 做原型（理由见下面「默认建议」），同样问一句「就这样可以吗」。
  - 用户想换引擎、或想多了解，再把下表和「界面」的说明给用户看，由用户拍板。用户选了 Unity，再一并问两件事：能不能接受 PuerTS（见下面「界面」），要不要先做网页原型（默认要）。

  下表只是例子，**以各引擎和平台的官方文档为准**：

  | 发布目标 | 推荐 |
  | --- | --- |
  | 网页、Lumio | 网页 + LGUI |
  | 微信 / 抖音小游戏 | Unity（用它的小游戏适配）或 Cocos Creator |
  | Steam / PC | Unity；重 3D 可以用 UE，也可以用 Godot |
  | 安卓、iOS | Unity，也可以用 Godot |
  | 多个目标 | 能覆盖全部目标的那个，通常是 Unity |

- **界面一律推荐 [LGUI](https://github.com/LumioGames/LGUI)**：
  - 网页：直接用。
  - Unity：LGUI 官方首先支持的引擎（Unity 6000.6.x + PuerTS 3.0.3，见 LGUI 仓库 `plugin/references/unity.md`）。选 Unity 时先问用户能不能接受用 PuerTS（TypeScript）作为引擎里的脚本 / 热更语言：能接受就用 LGUI，界面在 LGUI 里做好再导出到 Unity；不能接受就用 Unity 自带的 UI。
  - Cocos、LayaAir、UE 等：照实告诉用户，LGUI 可以接这些引擎，但适配层还没做；可以先用 LGUI 在网页里做原型验证玩法，正式界面用引擎自带的 UI。
- **默认建议：先用网页 + LGUI 做原型**，玩法验证得差不多了再转到 Unity；用户不要原型时，`Client/README.md` 直接写 Unity 建工程的步骤。理由：网页原型改得快、在浏览器里就能试玩；LGUI 支持 `lgui unity export` 快速转过去；用户接受 PuerTS 时，TypeScript 写的游戏代码也能带到 Unity，不接受时网页原型只用来验证玩法。
- **默认值**：网页（界面用 LGUI）。

## 不问，直接用默认值

- **几个人做**：默认一个人，`{{人数}}` 写「一个人做」，`workflow.md` 按一个人填（直接在 `main` 上存档，不开分支），不跟用户讲分支。用户自己提到有别人一起做（「我和朋友一起做」「我们三个人」）时，再问几个人、要不要现在就备份到云端方便大家一起改（要一个 GitHub 账号），然后按多人填 `workflow.md`（功能分支加 PR；跟用户只说「各做各的，做完合到一起」）。
- **英文短名**：小写字母、数字和连字符（如 `star-hop`），以后用作工程名和打包文件名。Agent 自己起：有用户自己的远程仓库（`git remote -v` 指向的不是 LumioTemplate）就用那个仓库名；否则按暂定名意译一个。在复述里告诉用户，标「Agent 代定，可以改」，用户不满意再改。
- **文档和注释的语言**：默认跟用户说话的语言一致，记作 `{{语言}}`。用户要文档和注释用不同语言，写进 `code-style.md`。

## 答案之间要提醒的地方

- **发布目标里有 Lumio，引擎又不是网页**：告诉用户 Lumio 收的是网页包（ZIP 里直接放入口 HTML 和 `lumio.json`，见 `.spec/knowledge/lumio-platform/publishing.md`）；这个引擎能不能导出成这样的网页包，建工程时再确认。照用户的选择生成，不替用户改路线。
- **有自己的服务端，又要发布到 Lumio**：告诉用户平台的好友、私信、联机能力不对第三方开放；游戏可以连自己的服务器，地址要在 `lumio.json` 的 `network.connect` 里写成精确的 `https://` 或 `wss://` 来源（见 `.spec/knowledge/lumio-platform/sdk.md` 和 `publishing.md`）。
