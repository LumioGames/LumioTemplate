# 项目红线

{{暂定名}}的项目红线：只写「必须 / 只能 / 不得」，后面一句话说为什么。通用红线在 `.spec/rules/system.md`（框架文件，不改）；做法和细节在 `.spec/knowledge/`。用户新定下的项目红线加在本文件末尾，一条一节。

## 模块边界

- **`Config/` 不得依赖任何模块。**——它是数值和格式的唯一来源，反过来依赖会让改表牵动代码。
<!-- 如果：有 Server -->
- **`Client/` 和 `Server/` 不得互相引用代码，只能通过 `Config/` 里的协议对齐。**——两端各自部署，直接引用会把一端的改动悄悄带到另一端。
<!-- 结束 -->
- **产品代码不得引用 `Tools/`。**——工具只在开发时用，打进产品就是多余的代码和风险。
- **数值必须放在 `Config/`，不得写死在代码里。**——策划改数值不该改代码，写死的数值也没法统一查。
- **构建产物只能放在 `Builds/`，不得提交进 git。**——产物能从源码重新构建，提交了只会让仓库变大、和源码对不上。构建产物、工具缓存和要提交的生成物怎么区分，见 `.spec/knowledge/standards/code-style.md`「生成物」。

## 文档

写进 `.spec/` 的内容分三类，各有各的门槛：

- **产品决策（范围、玩法、美术方向、数值）只写用户拍板的；讨论中的想法留在对话里。**——没定的内容写进去，以后的 Agent 会把它当成定论。
- **工程事实（复现过的 bug、工具限制、测试结果）由 Agent 带上证据直接记，不用另外问用户。**——证据是复现步骤、命令和关键输出；事实不记，下一个 Agent 还会再踩一遍。
- **没验证过的猜测不得写成结论。**——要记就标「未验证」，并写清怎么验证；猜测冒充事实，比没有记录更误导人。

## 用户电脑

- **装 Node、Git 必须先征得用户同意（一次同意覆盖这一次要装的），只能走 `.spec/knowledge/lumio-platform/environment.md` 写的官方渠道；引擎等其他系统软件不替用户装；不得修改用户电脑的系统设置，不得替用户输入密码。**——开发离不开 Node 和 Git，替新手装能少走弯路；但装软件是动用户的电脑，要用户点头，来源要可信。
- **密钥、令牌不得写进客户端代码。**——客户端代码玩家都能拿到。

## 发布到 Lumio：连接平台

做法和细节在 `.spec/knowledge/lumio-platform/`。

- **正式构建只能用 `connectLumioFromLaunch()` 连平台；连接失败时必须把错误显示给玩家，不得自动换成模拟器或本地假数据。**——在平台上假装成功会让玩家以为进度已存好，实际已经丢了。
- **模拟器只能在本地开发构建里用，并且必须在构建时剔除。**——检查办法：正式构建的脚本里搜不到 `simulated_friend`（只有模拟器模块里有）。
- **不得启用 SDK 的 `firstParty` 选项；不得调用好友、私信、联机接口。**——这些首版只对平台自己的应用开放，声明了也不会授予。
- **每次调用都必须检查返回的 `ok`，失败时按 `failure.code` 给出明确提示，不得伪造成功或静默吞掉。**
- **存档写入必须带上读出来的 `expectedRevision`（新槽用 `null`）；遇到冲突必须保留玩家当前进度、重新读取后让玩家决定，不得自动覆盖云端。**

## 发布到 Lumio：打包与上传

- **ZIP 根目录必须直接放入口 HTML 和 `lumio.json`，不得再套一层文件夹。**——平台按包根找文件。
- **`lumio-bootstrap.js` 不得放进 ZIP。**——它由平台在上线时注入；入口页可以用相对路径 `./lumio-bootstrap.js` 引用它。
- **页面里的资源路径必须是相对路径，不得以 `/` 开头。**——游戏在平台上不在域名根目录。
- **上传的只能是构建产物，不得依赖 `node_modules`、开发服务器或本机文件。**
- **用到的存档槽、游戏字段、排行榜必须先在 `lumio.json` 里声明；外部网络只能声明精确的 https / wss 来源，不得用通配或平台域名。**
- **打包必须用 `.spec/tools/lumio-pack.mjs`（或做同样检查的工具）。**——它先按平台规则检查，避免打出注定被拒的包。
- **发布只能走 `publishing.md` 写的两种方式之一，由用户选：A 由用户在创作中心自己上传、提交审核；B 只有用户选了 B、并自己把作者 API 密钥设进环境变量后，Agent 才能用 API 发布，创建作品、修改公开资料、提交审核前都必须先问用户。**——发布是对外操作，每一次都要用户点头。
- **作者 API 密钥只能放在环境变量里，不得写进代码、配置文件、仓库或 ZIP，不得放进命令行参数、日志和截图，不得让用户贴进对话。**——密钥能改作品、提交审核，泄露了别人就能以作者身份发布。

## 发布到 Lumio：账号与数据

- **游戏里不得做账号密码登录，不得索取或保存平台账号、Cookie、令牌。**——登录和资料授权由平台负责，游戏只拿到本游戏的玩家号和玩家同意给的资料。
